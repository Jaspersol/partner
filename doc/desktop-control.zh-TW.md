# 桌面操控

[简体中文](./desktop-control.md) | **繁體中文** | [English](./desktop-control.en.md)

返回 [文件目錄](./README.zh-TW.md)。

開啟後，模型可以查看視窗、操作控制項、輸入文字和啟動程式。功能預設關閉；啟用後，相關工具由桌面子 agent 持有，主 agent 只能委派（見 [子 agent](./sub-agents.zh-TW.md)）。

## 開啟

前往「設定 → 電腦操控」：

- **允許助手操作電腦**：桌面操控總開關。
- **允許執行系統指令**：獨立開關，預設關閉，且必須先開啟電腦操控。指令只會在「全部審批」檔位下逐次詢問，視窗租約不能免除指令審批。
- **只允許操作這些視窗**：視窗白名單；留空表示不限制。
- **操作時佔用螢幕嗎**：選擇前景、自動或背景模式，詳見下方「背景輸入」。
- 若要讓模型讀取截圖，請在「設定 → 對話模型」開啟「能看圖片」。純文字模型不會註冊截圖工具。

GUI 應用程式、指令與 MCP 外部程序依系統權限存取檔案，不會繼承原生檔案工具白名單；MCP 免審批清單也不是檔案授權。需要系統級隔離時請使用系統安全措施，指令字串過濾不能當作沙箱。原生檔案工具不可用或失敗時，應說明原因並調整權限、目標或參數，不要從這些入口繞過限制。

## 工具

| 工具 | 作用 | 審批 |
|---|---|---|
| `desktop_observe` | 列出視窗和其中的可互動控制項 | 不需要 |
| `desktop_screenshot` | 截取視窗或整個桌面，疊加座標格線和控制項編號 | 不需要 |
| `desktop_act` | 聚焦、點擊、雙擊、右鍵、按鍵（含組合鍵）、打字、捲動和拖曳 | 依檔位 |
| `desktop_wait` | 等待控制項、視窗出現或畫面穩定，最多 5 秒 | 不需要 |
| `desktop_clipboard_get` / `_set` | 讀取或寫入剪貼簿 | 寫入需要 |
| `desktop_launch` | 啟動程式或開啟 URI；單純名稱會先查開始功能表 | 需要 |
| `desktop_exec` | 執行指令並回傳輸出，逾時 30 秒 | 僅全部審批 |

## 先找控制項再操作

- 觀察結果會回傳控制項和點擊位置；動作應用 `elementId` 指定目標，不要讓模型猜座標。
- 控制項支援 UI Automation pattern 時直接呼叫，例如按鈕、清單項目和核取方塊，不必把視窗帶到前景。
- 動作完成後預設附上該視窗的新截圖（`feedback=auto`），也可以選擇 `on-failure` 或 `off`。
- Chromium / Electron 應用的頁面控制項通常可由 UI Automation 直接發現，不需要偵錯連接埠；用 `desktop_launch` 啟動時還會開啟偵錯連接埠，使背景輸入和頁面節點更完整。

## 審批檔位

在工作階段輸入區的下拉選單切換，變更會立即生效：

| 檔位 | 桌面動作 |
|---|---|
| 不審批 | 桌面動作和指令都不詢問 |
| 危險指令審批 | 啟動程式、寫剪貼簿和系統快速鍵（Win 組合鍵、Alt+F4、Alt+Tab、Ctrl+Alt+*、Ctrl+Shift+Esc）需要批准；指令不詢問 |
| 全部審批（預設） | 介面動作依視窗租約審批，指令逐次審批；觀察和截圖不詢問 |

審批提示出現在工作階段輸入框正上方，沒有回應就視為拒絕。在「全部審批」下，一次批准並由執行管線接受後，同一視窗可繼續執行 10 步，租約在 10 分鐘內有效。指令、啟動、寫剪貼簿和系統快速鍵仍然每次詢問；系統快速鍵也不會消耗這 10 步租約。取消、逾時或設定失效後才抵達的批准不會留下租約。租約綁定授予時的設定版本，設定變更後不能繼續使用。

桌面變更動作會在本程序內序列執行。治理決策綁定決定當下的設定版本：等待審批或排隊期間，只要有任何設定儲存或重載，尚未開始的動作便會失效；即使之後把審批檔位改回原值也不會恢復，必須按目前設定重新發起並審批。鎖內檢查不會再次消耗任務租約。關閉桌面能力同樣會拒絕尚未開始的動作。逾時不能證明動作沒有發生，應先觀察現況，再決定是否重試。

## 護欄

所有護欄都會在注入輸入前檢查：

- 按鍵和打字要求目標視窗位於前景，否則先聚焦。
- 座標必須位於目標視窗及虛擬桌面內；越界會直接拒絕，不會夾到邊緣。
- 落點被其他視窗遮住時，會先嘗試把目標帶到前景；失敗則拒絕並說明遮擋視窗。
- 最小化視窗不能截圖或點擊，必須先聚焦還原。
- 結果會寫明目標視窗，並分開報告「是否已發出」和「畫面是否改變」。第一行是 `{"code","delivery","retry"}`：護欄拒絕為 `not_delivered` + `safe`；已發出但未確認效果為 `posted_unverified` + `unsafe`。
- 密碼欄位（UI Automation 的 `IsPassword`，或頁面 `type=password` / `autocomplete` 含 password 的輸入框）不會輸出值；寫入後只比較「空/已填」狀態。
- 系統快速鍵要單獨審批：任何含 Win 的組合、Alt+F4、Alt+Tab、Ctrl+Alt+* 及 Ctrl+Shift+Esc。批准不會授予任務租約。
- 對帶有 `elementId` 的按鍵或打字，先呼叫 SetFocus，再確認 `HasKeyboardFocus`。若焦點不在目標控制項上，便拒絕並指出目前焦點。
- 同一視窗內身分相同的控制項會標記為 `ambiguous`；依 `elementId` 操作會回傳 `AMBIGUOUS_TARGET`，要求改用座標或縮小觀察範圍。
- 截圖前後會核對視窗代碼、行程啟動時間和矩形。期間視窗移動或被替換時，該張圖會丟棄。
- 卡住的視窗先用 `SendMessageTimeout(WM_NULL, 2s)` 預探測；回傳 `APP_UNRESPONSIVE` 時不進入 UI Automation。

## 背景輸入

「操作時佔用螢幕嗎」對應 `desktop.inputMode`：

| 值 | 行為 |
|---|---|
| `foreground`（預設） | 能使用控制項 pattern 或頁面協定時優先使用，否則接管前景 |
| `auto` | 能在背景完成就在背景，必要時才接管螢幕 |
| `background` | 絕不接管螢幕；無法在背景完成時拒絕並提供替代方案 |

背景通道只有兩條：頁面偵錯協定（只適用於 `desktop_launch` 啟動的瀏覽器 / Electron）和 UI Automation pattern。使用者已經開啟的程式沒有偵錯連接埠。

## UIA 用戶端

- 使用 UI Automation COM 介面（`CUIAutomation8`），固定在專用 MTA 執行緒呼叫；連線逾時 2 秒，交易逾時 5 秒。等待 Chromium 樹穩定在呼叫方執行，不佔用 UIA 佇列。
- 跨行程 provider 使用 `CacheRequest`（`AutomationElementMode_Full`）一次取回遍歷所需屬性；同一行程的 provider 不使用快取。本機同一個 21 節點夾具實測快取 48.4ms、未快取 27.6ms。快取請求不能採用預設的 `None`：實測 Edge 頁面只回傳 63 個而非 129 個節點。
- 本機比較：Notepad 43/43、Explorer 7/7、Chromium 視窗 87/87、Edge 頁面 127/127 個節點（COM 與受控用戶端相同）；單視窗 observe p50 為 Explorer 6.9ms、Chromium 61.7ms（控制項上限 40）和 Edge 頁面 327.0ms。
- 本機實測為單屏 2560×1440、系統 DPI 96（100%）、虛擬桌面原點 (0,0)。雙屏、負座標副屏及 125%/150% 縮放尚未實測。驗證時應同時比較代碼、邊界、主屏標誌和縮放比例，不要依 `GetProcessDpiAwareness` 的讀回值斷言 Per-Monitor V2。

## 已知邊界

- 偵錯連接埠沒有驗證，監聽本機迴路位址，本機其他行程也能存取。只有 `desktop_launch` 主動啟動程式時才會開啟。
- 沒有 OCR；UI Automation 看不到的介面要交給視覺模型讀取截圖。
- 同樣只實測單螢幕 2560×1440、DPI 96（100%）和原點 (0,0)。雙螢幕、負座標副螢幕及 125%/150% 縮放仍未測試；驗證時必須綜合比較代碼、邊界、主螢幕標誌和縮放比例，不要只依 `GetProcessDpiAwareness` 讀回值判斷 Per-Monitor V2。
- 本機沒有重現 Chromium 冷啟動時「第一次讀取偏少、之後穩定」的行為；程式仍保留每 250ms 重讀直到節點數穩定的邏輯。
- 真實 Electron 應用程式（例如音樂用戶端）的頁面控制項路徑尚未驗證。
