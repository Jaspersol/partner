# 子 agent

**简体中文** | [繁體中文](./sub-agents.zh-TW.md) | [English](./sub-agents.en.md)

返回 [文档目录](./README.md)。

主 agent 只对话和派活。点窗口、读文件这类耗时的活交给子 agent 在后台做，做完把结果作为一条新输入回报，主 agent 再转述给你。

## 场景

场景是固定的两项，每个场景最多一个子 agent：

| 场景 | 子 agent 的工具 | 开关 | 谁来占用 |
|---|---|---|---|
| `desktop` 桌面操控 | `desktop_*` | `desktop.enabled` | 内置“桌面操控”子 agent，不可删 |
| `file-read` 文件访问 | `file_list`、`file_read`；符合写入条件时还有 `file_write`、`file_edit`（编辑须支持 NTFS 事务） | `files.enabled` + 读取白名单；写入另需 `files.writeEnabled` + 写入白名单（均默认关） | 用户自己新增 |

- 没人占用的场景由主 agent 自己执行。例如开了读文件但没建读文件子 agent，`file_*` 工具就给主 agent。
- 桌面例外：桌面工具从不给主 agent。开启桌面就必须有启用的桌面子 agent，保存时会校验。

## 派活与回报

- 主 agent 有三个工具：`agent_delegate`（立即返回）、`agent_job_status`、`agent_job_cancel`。
- 任务在后台跑，不占主对话。结束后汇报进入同一条队列，主 agent 起新的一轮来转述。
- 每个任务有自己的会话日志（`agents/<agent>/job-*/session/`）；每个 agent 只保留最近 30 个任务。截图和读到的文件内容不进主会话，也不进记忆。
- 一个子 agent 同时只跑一个任务。同一目标刚失败，10 分钟内不能原样再派。
- 进程崩溃后，没结束的任务会在下次启动时补一条“已中断”的汇报。

## 重试与失败

- 每个任务最多跑 `maxRounds` 轮，默认 5（可调 1–10）。总时限 15 分钟。
- 成败由子 agent 调用 `task_report` 判定：成功要带证据，失败要带错误。没调用就算失败。
- 审批被拒、治理拒绝、取消、超时等终止类失败不重试。其余失败重试前，会把上一轮已执行的动作告诉子 agent，要求先看现状。
- 全部失败时，主 agent 收到原因类别、最后一次错误和逐轮记录，并被要求如实转告，不能说成功。

## 提示词与模型

在「设置 → agent」页编辑：

- 主 agent 和每个子 agent 都有可编辑的提示词。没改过就用内置默认，升级后自动拿到新默认。
- 末尾自动生成的文件工具边界、“可委派场景”和“汇报方式”不可编辑；文字和语音请求遵循同一边界。
- 改提示词不重启消费者，下一轮生效。
- 子 agent 的模型默认跟随主模型，也可以单独配，比如桌面子 agent 用视觉模型。

## 文件访问的边界

- 原生文件工具支持列目录、读取，以及符合条件时新建和编辑文件。直接文件请求必须使用相应原生工具；未调用、不可用、被拒绝或失败时，不应声称成功或改走桌面、命令或 MCP。用户明确要求通过某个应用办理的桌面任务除外。
- `files.writeEnabled` 默认关闭，`files.writeRoots` 默认空；旧设置不会自动取得写权限。启用时须配置至少一个已存在的绝对目录。`file_write` 仅支持 Windows 本地 NTFS，目标须同时位于读取和写入白名单内，每次明确批准；只新建，不覆盖已有文件或编辑原件。
- 新建要求已存在的父目录，不创建目录；不支持网络盘、特殊路径或重解析点，并拒绝 Partner 数据和凭据路径。文件为 UTF-8 无 BOM。若创建失败或结果未确认，不应声称成功或自动重试；检查目标及权限后再决定如何操作。
- `file_edit` 在相同白名单和单次审批规则下，按 `file_read` 返回的 SHA-256 版本精确替换唯一匹配的 UTF-8 文本。编辑只写原文件对象的默认数据流，保留 BOM、安全描述符和备用数据流；成品上限为 8 MiB。仅在支持 Windows [NTFS 事务（TxF）](https://learn.microsoft.com/en-us/windows/win32/fileio/transactional-ntfs-portal) 的本地卷上执行。提交时在事务锁内复核版本和硬链接；版本变化、存在多个硬链接、事务不可用或目标不受支持时拒绝，无非事务回退。
- 这是给 agent 的提示约定，不是系统沙箱：桌面应用、命令和 MCP 按系统权限访问文件，不继承文件白名单；MCP 免审批清单也不是文件授权。需要系统级隔离时应使用系统安全措施。
- 路径必须在 `files.roots` 内。`..` 穿越和指向目录外的链接都拒绝。
- Windows 和 Linux 上读取和目录列举检查已打开句柄的实际路径；无法验证的平台拒绝。Windows 拒绝备用数据流；硬链接别名仍无法据此识别为受保护文件，白名单不是文件系统沙箱。
- `file_list` 按目录在前、名称不区分大小写排序（同名大小写差异按序号字符排序），默认从 `offset: 0` 返回最多 200 项；可指定非负整数 `offset` 和 1–200 的 `limit`，有后续项时用返回的下一页 offset 继续，保留相同的 `path` 和 `limit`。每次调用重新列举目录，不是快照：增删或重命名可能使翻页重复或遗漏，目录变化时应从头重列。
- 只读文本，按段读取，单段默认 12000、上限 40000 字符；二进制和超过 8 MB 的文件拒绝。
- `file_read` 的 offset 和 limit 按 UTF-16 代码单元计数；不会拆开代理对，若 limit 太小或 offset 位于代理对中间会返回参数错误。
- 单页超过上下文结果预算时不会返回不完整页面；请保持路径和 offset，减小 limit 后重试。
- 每次读取返回所读字节的 SHA-256 版本；分页之间文件可能改变，应比较版本。版本不是文件锁，也不保证后续读取一致。
- 目录内也不读 `.env*`、`*.pem`、`*.key`、`*.pfx` 等密钥文件，以及整个工作区。
- 读到的内容会进模型上下文，白名单别配得太宽。
