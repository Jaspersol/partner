# 子 agent

**简体中文** | [繁體中文](./sub-agents.zh-TW.md) | [English](./sub-agents.en.md)

返回 [文档目录](./README.md)。

主 agent 负责对话和任务分派。窗口操作、文件读取等耗时工作可交给子 agent 在后台执行；完成后，子 agent 会把结果作为新的输入回报，再由主 agent 转述。

## 场景

场景固定为两类，每类最多由一个子 agent 负责：

| 场景 | 子 agent 可用工具 | 开关 | 使用者 |
|---|---|---|---|
| `desktop` 桌面操控 | `desktop_*` | `desktop.enabled` | 内置“桌面操控”子 agent，不可删除 |
| `file-read` 文件访问 | `file_list`、`file_read`；具备写入条件时还包括 `file_write`、`file_edit`（编辑需要 NTFS 事务支持） | `files.enabled` 和读取白名单；写入还需 `files.writeEnabled` 与写入白名单（都默认关闭） | 用户自行添加 |

- 没有子 agent 占用的场景由主 agent 直接处理。例如，开启文件读取但没有创建读文件子 agent 时，`file_*` 工具会交给主 agent。
- 桌面操控是例外：桌面工具绝不会交给主 agent。开启该功能时必须同时有已启用的桌面子 agent，保存设置时会校验这一条件。

## 任务分派与回报

- 主 agent 可使用 `agent_delegate`（立即返回）、`agent_job_status` 和 `agent_job_cancel` 三个工具。
- 任务在后台运行，不会占用主对话。结束后的汇报进入相同队列，由主 agent 新开一轮向你转述。
- 每项任务都有独立的会话日志，位置为 `agents/<agent>/job-*/session/`；每个 agent 只保留最新 30 项任务。截图和读取到的文件内容不会进入主会话或记忆。
- 一个子 agent 同一时间只运行一个任务。若某个目标刚失败，10 分钟内不能不作调整就再次分派给它。
- 程序崩溃后，尚未完成的任务会在下次启动时收到一条“已中断”汇报。

## 重试与失败

- 每项任务最多运行 `maxRounds` 轮，默认 5 轮，可设置为 1–10 轮；总执行时间上限为 15 分钟。
- 子 agent 通过调用 `task_report` 报告成功或失败。成功报告必须附证据，失败报告必须提供错误；未调用该工具视为失败。
- 审批被拒、治理拒绝、取消、超时等终止类错误不会重试。其他错误在重试前会将上一轮已经执行的动作告知子 agent，并要求先检查当前状态。
- 所有轮次均失败时，主 agent 会收到失败类别、最后一次错误和每轮记录，并被要求如实转告，不能把失败说成成功。

## 提示词与模型

在“设置 → agent”页面进行配置：

- 主 agent 和每个子 agent 都有独立的可编辑提示词。未修改的提示词使用内置默认值，应用升级时也会获取新版默认值。
- 自动追加的文件工具边界、“可委派场景”和“汇报方式”不可编辑；文字和语音请求都遵循同一边界。
- 修改提示词无需重启消费者，下一轮开始时生效。
- 子 agent 默认使用主模型，也可以单独指定模型，例如为桌面子 agent 配置视觉模型。

## 文件访问边界

- 原生文件工具能列目录和读取文件；满足条件时也可新建或编辑。用户直接要求处理文件时必须使用相应原生工具。若工具未调用、不可用、被拒绝或执行失败，不应声称操作成功，也不能改用桌面、命令或 MCP 绕过；用户明确要求通过某个应用完成的桌面任务除外。
- `files.writeEnabled` 默认关闭，`files.writeRoots` 默认为空；旧设置不会自动获得写权限。启用时至少要提供一个已存在的绝对目录。`file_write` 仅支持 Windows 本地 NTFS，目标必须同时位于读取与写入白名单中。“不审批”档位可直接执行，其他档位每次都要明确批准。该工具只能新建文件，不覆盖现有文件，也不编辑原件。
- 新建文件时父目录必须已经存在，工具不会创建目录。不支持网络磁盘、特殊路径或重解析点，也会拒绝 Partner 数据目录和凭据路径。输出为无 BOM 的 UTF-8。创建失败或结果未确认时，不能声称成功或自动重试；应先检查目标与权限，再决定后续操作。
- `file_edit` 遵守同一套白名单和审批规则，根据 `file_read` 返回的 SHA-256 版本，对 UTF-8 文本执行精确且唯一的替换。编辑只写入原文件对象的默认数据流，并保留 BOM、安全描述符和备用数据流；最终文件不得超过 8 MiB。操作仅支持具备 Windows [NTFS 事务（TxF）](https://learn.microsoft.com/en-us/windows/win32/fileio/transactional-ntfs-portal) 能力的本地卷。提交时会在事务锁内再次检查版本与硬链接；若版本变化、存在多个硬链接、事务不可用或目标类型不支持，就拒绝操作，不会退回非事务写入。
- 这些内容是 agent 的行为约定，不构成系统沙箱。桌面应用、命令和 MCP 按系统权限访问文件，不继承文件白名单；MCP 免审批清单也不是文件授权。需要系统级隔离时应采用系统安全措施。
- 所有路径都必须位于 `files.roots` 中。`..` 路径穿越，以及指向根目录外的链接，都会被拒绝。
- Windows 和 Linux 的读取及目录列举会检查已打开句柄的实际路径；无法验证的平台会拒绝操作。Windows 上不允许备用数据流。此检查仍不能识别指向受保护文件的硬链接别名，因此白名单不是文件系统沙箱。
- `file_list` 先列目录，再按不区分大小写的名称排序；大小写相同的名称再按序数字符排序。默认从 `offset: 0` 开始，最多返回 200 项。可指定非负整数 `offset` 和 1–200 的 `limit`；有下一页时使用返回的 offset，并保持相同的 `path` 与 `limit`。每次调用都会重新列举，不是目录快照：新增、删除或改名可能造成重复或遗漏，目录发生变化后应从头列举。
- 只读取文本并按段返回，单段默认 12000 字符，最高 40000 字符；二进制文件和大于 8 MB 的文件会被拒绝。
- `file_read` 的 `offset` 与 `limit` 以 UTF-16 代码单元计数，不会切开代理对。若 limit 太小或 offset 落在代理对中间，会返回参数错误。
- 单页结果超过上下文预算时不会返回不完整内容。保持原来的路径和 offset，缩小 limit 后重试。
- 每次读取会返回所读字节的 SHA-256 版本。文件可能在分页期间改变，因此应比较版本；这个版本不是文件锁，也不保证后续读取内容一致。
- 即便位于允许目录中，也不会读取 `.env*`、`*.pem`、`*.key`、`*.pfx` 等密钥文件，也不会读取整个工作区。
- 读取内容会进入模型上下文，因此文件白名单不宜设置过宽。
