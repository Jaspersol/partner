# 桌面操控

**简体中文** | [繁體中文](./desktop-control.zh-TW.md) | [English](./desktop-control.en.md)

返回 [文档目录](./README.md)。

启用后，模型可以查看窗口、操作控件、输入文字以及启动程序。该能力默认关闭；开启后，相关工具由桌面子 agent 持有，主 agent 只能委派任务（见 [子 agent](./sub-agents.md)）。

## 开启

进入“设置 → 电脑操控”：

- **允许助手操作电脑**：桌面操控总开关。
- **允许执行系统命令**：单独的开关，默认关闭，并且必须先开启电脑操控。命令只有在“全部审批”档位下才会逐次询问，窗口租约不能替代命令审批。
- **只允许操作这些窗口**：窗口白名单；留空表示不限制目标窗口。
- **操作时占用屏幕吗**：可选前台、自动或后台模式，详见下方“后台输入”。
- 如果需要模型读取截图，请在“设置 → 对话模型”中开启“能看图片”。纯文本模型不会注册截图工具。

GUI 应用、命令以及 MCP 外部进程按照系统权限访问文件，不会继承原生文件工具的白名单；MCP 的免审批清单也不是文件授权。需要系统级隔离时应使用系统安全机制，命令字符串过滤不能当作沙箱。原生文件工具不可用或失败时，应说明原因并调整权限、目标或参数，不要从这些入口绕过限制。

## 工具

| 工具 | 作用 | 审批 |
|---|---|---|
| `desktop_observe` | 列出窗口及窗口内的可交互控件 | 不需要 |
| `desktop_screenshot` | 截取窗口或整个桌面，并叠加坐标网格和控件编号 | 不需要 |
| `desktop_act` | 聚焦、点击、双击、右键、按键（含组合键）、打字、滚动和拖拽 | 按档位决定 |
| `desktop_wait` | 等待控件出现、窗口出现或画面稳定，最多 5 秒 | 不需要 |
| `desktop_clipboard_get` / `_set` | 读取或写入剪贴板 | 写入需要 |
| `desktop_launch` | 启动程序或打开 URI；裸名称会先查开始菜单 | 需要 |
| `desktop_exec` | 执行命令并返回输出，超时 30 秒 | 仅全部审批 |

## 先找控件再操作

- 观察结果会返回控件及其点击点；执行动作时用 `elementId` 指定目标，不让模型猜坐标。
- 控件支持 UI Automation pattern 时直接调用，例如按钮、列表项和复选框，不要求窗口位于前台。
- 动作完成后默认附带该窗口的新截图（`feedback=auto`）；也可以选择 `on-failure` 或 `off`。
- Chromium / Electron 应用的页面控件通常可以通过 UI Automation 直接发现，无需调试端口；使用 `desktop_launch` 启动时还会额外打开调试端口，使后台输入和页面节点信息更完整。

## 审批档位

在会话输入区的下拉菜单中切换，修改会立即生效：

| 档位 | 桌面动作 |
|---|---|
| 不审批 | 桌面动作和命令都不询问 |
| 危险指令审批 | 启动程序、写剪贴板和系统级快捷键（Win 组合键、Alt+F4、Alt+Tab、Ctrl+Alt+*、Ctrl+Shift+Esc）需要批准；命令不询问 |
| 全部审批（默认） | 界面动作按窗口租约审批，命令逐次审批；观察和截图不询问 |

审批提示显示在会话输入框正上方，没有回答就视为拒绝。在“全部审批”下，一次批准并由执行管线接受后，同一窗口可以继续执行 10 步，租约在 10 分钟内有效。命令、启动、写剪贴板和系统快捷键仍然每次询问；系统快捷键也不会消耗这 10 步租约。审批取消、超时或设置失效后到达的批准不会创建租约。租约绑定授予时的设置版本，设置变更后不能继续使用。

桌面变更动作在当前进程内串行执行。治理决定绑定决定作出时的设置版本：在等待审批或排队期间，只要有任何设置保存或重载，尚未开始的动作就会失效，即使随后把审批档位改回原值也不会恢复；必须按当前设置重新发起并审批。锁内检查不会再次消耗任务租约。关闭桌面能力同样会拒绝尚未开始的动作。出现超时不能证明动作没有发生，应先观察当前状态，再决定是否重试。

## 护栏

所有护栏都会在注入输入前执行检查：

- 按键和打字要求目标窗口处于前台，否则会先聚焦目标。
- 坐标必须同时位于目标窗口和虚拟桌面内；越界点会直接拒绝，不会夹到边缘。
- 如果落点被其他窗口遮挡，会先尝试把目标窗口带到前台；失败时拒绝操作并说明遮挡窗口。
- 最小化窗口不能截图或点击，必须先聚焦并还原。
- 结果会写明目标窗口，并分别说明“是否已发出”和“画面是否发生变化”。第一行是 `{"code","delivery","retry"}`：护栏拒绝返回 `not_delivered` + `safe`；已发出但未确认效果返回 `posted_unverified` + `unsafe`。
- 密码字段（UI Automation 的 `IsPassword`，或页面中 `type=password` / `autocomplete` 含 password 的输入框）不会输出值；写入后只比较“空/已填”状态。
- 系统快捷键单独审批：包括任何带 Win 的组合、Alt+F4、Alt+Tab、Ctrl+Alt+* 和 Ctrl+Shift+Esc。批准它们不会授予任务租约。
- 对带 `elementId` 的按键或打字，先调用 SetFocus，再确认 `HasKeyboardFocus`。如果焦点没有落在目标控件上，就拒绝并指出当前焦点。
- 同一窗口内身份相同的控件会标记为 `ambiguous`；按 `elementId` 操作时返回 `AMBIGUOUS_TARGET`，要求改用坐标或缩小观察范围。
- 截图前后会核对窗口句柄、进程启动时间和矩形。期间窗口移动或被替换时，该截图会被丢弃。
- 对卡住的窗口先用 `SendMessageTimeout(WM_NULL, 2s)` 预探测；若返回 `APP_UNRESPONSIVE`，就不进入 UI Automation。

## 后台输入

“操作时占用屏幕吗”对应 `desktop.inputMode`：

| 取值 | 行为 |
|---|---|
| `foreground`（默认） | 能用控件 pattern 或页面协议时优先使用，否则接管前台 |
| `auto` | 尽量在后台完成，无法后台执行时再接管屏幕 |
| `background` | 绝不接管屏幕；无法后台完成时拒绝并给出替代方案 |

后台只有两条通道：页面调试协议（仅适用于由 `desktop_launch` 启动的浏览器 / Electron）和 UI Automation pattern。已经由用户打开的程序没有调试端口。

## UIA 客户端

- 使用 UI Automation COM 接口（`CUIAutomation8`），固定在专用 MTA 线程中调用；连接超时 2 秒，事务超时 5 秒。等待 Chromium 树稳定在调用方执行，不占用 UIA 队列。
- 跨进程 provider 使用 `CacheRequest`（`AutomationElementMode_Full`）一次取回遍历所需属性；同进程 provider 不使用缓存。本机同一 21 节点夹具实测缓存耗时 48.4ms，未缓存为 27.6ms。缓存请求不能使用默认的 `None`：实测 Edge 页面只返回 63 个节点，而不是 129 个。
- 本机对比结果：Notepad 43/43、Explorer 7/7、Chromium 窗口 87/87、Edge 页面 127/127 个节点（COM 与托管客户端结果相同）；单窗口 observe 的 p50 为 Explorer 6.9ms、Chromium 61.7ms（控件上限 40）和 Edge 页面 327.0ms。
- 本机实测环境为单屏 2560×1440、系统 DPI 96（100%）、虚拟桌面原点 (0,0)。双屏、负坐标副屏以及 125%/150% 缩放尚未实测。验证时应综合比较句柄、边界、主屏标志和缩放比例，不要用 `GetProcessDpiAwareness` 的读回值断言 Per-Monitor V2。

## 已知边界

- 调试端口没有认证，监听本机回环地址，本机其他进程也能访问。只有 `desktop_launch` 主动启动程序时才会打开。
- 没有 OCR；UI Automation 无法看到的界面需要交给视觉模型读取截图。
- 本机同样只实测了单屏 2560×1440、DPI 96（100%）和虚拟桌面原点 (0,0)。双屏、负坐标副屏及 125%/150% 缩放尚未实测；验证仍应同时比较句柄、边界、主屏标志和缩放比例，不要依据 `GetProcessDpiAwareness` 读回值断言 Per-Monitor V2。
- 本机没有复现 Chromium 冷启动时“首次读取数量偏少、随后稳定”的情况；代码仍保留每 250ms 重读、直到数量稳定的逻辑。
- 真实 Electron 应用（例如音乐客户端）的页面控件路径尚未验证。
