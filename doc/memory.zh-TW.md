# 記憶

[简体中文](./memory.md) | **繁體中文** | [English](./memory.en.md)

返回 [文件目錄](./README.zh-TW.md)。

你說過「我用的是公司內網帳號 alice」，下次換個說法問，它想得起來。記憶存在本機 SQLite，每一條都能看、能改、能刪。

## 怎麼運作

| 環節 | 做法 |
|---|---|
| 寫入 | 從使用者原話自動提煉；排程輪次和助手執行複述不自動寫入通用記憶 |
| 召回 | 每輪請求前檢索相關記憶，在目前的使用者訊息前注入背景；額度不超過設定上限和上下文剩餘空間，不擠掉已選歷史 |
| 時效 | 注入的每條帶層級和時間，如 `[established, 10 天前]`，並提示模型以你現在說的為準 |
| 中文 | 另外建了 bigram 全文索引，中文檢索不靠全表掃描 |

子 agent 的回報不進記憶。

缺少明確對象的短指代可用目前可見對話中最近的使用者文字補充候選查詢，不取代原話；錯誤碼、檔名等明確識別符的完整匹配可獲得有限加分，原因寫入 `reasons`。管理介面 `POST /api/memory/recall` 只檢索提交的 `query`，不補對話上下文，也不使用對外服務的來源排除或注入預算。

滾動摘要、背景召回和原文回讀各有用途：壓縮把舊對話折疊為滾動摘要，摘要中的事實不會自動寫入長期記憶；每輪背景召回從 SQLite 選相關記錄。主 agent 也可按需用 `session_history` 搜尋目前工作區的歷史，或按 `Seq` 分頁讀取正文；它不會自動注入原文。搜尋和讀取可以看到壓縮隱藏的原文及最新修訂，但不會顯示其他撤回的內容；實體刪除（purge）後無法讀取，也不會從摘要或備份還原。工具結果只能回讀實際入庫的文字，入庫前被截斷的部分無法找回。

`session_history` 的 `day` 接受 `YYYY-MM-DD`、`today` 或 `yesterday`，按執行機器的本地時區及原始事件時間篩選，可結合 `query`；回傳絕對日期和最多 8 條記錄。續頁使用回傳的日期、原 `query` 和排他的 `beforeSeq`；正文可用 `seq` / `offset` 繼續讀取。沒有結果不會回退到其他日期。

相關性時效按來源記錄時間計算，重複召回不會讓舊事實變新。Working 記錄及其可檢索的晉升副本不會同時擠佔檢索候選；管理列表仍保留兩者。

## 四個層級

介面上顯示為：**剛記下 / 經歷 / 事實 / 做法**。

- 相似文字或同層同源不足以證明是同一事實，不自動使舊記錄失效；明確修訂仍可取代舊記錄。
- 三個月沒被召回的記錄降一級，最後由定期清理移除。
- 層級可以在記憶頁手動改。「這是我依賴的事實」只有你能判斷。

## 在記憶頁能做什麼

- 檢視全部記錄，包括已失效的，以及「什麼取代了它」「上次什麼時候用過」。
- 依層篩選，每層顯示數量。
- **固定**：固定的記錄不會被自動降級或清理，但仍可明確修訂。
- **新建**：手寫一條記憶，預設落在「事實」層，長度 4–400 字。
- 刪除單條記錄。

## 和對話刪除的關係

刪除或撤回一段對話時，由這段對話提煉出的記憶一起刪除。手寫的記憶不屬於任何一輪對話，不會跟著刪。

## 對外服務寫入的記憶

[對外服務](./services.zh-TW.md)會把遊戲 mod、外掛等外部程式的互動總結成一句話寫進主記憶，以 `[对外服务:<名稱>]` 開頭。記憶頁替這些記錄標出來源服務，可以用「按來源篩選」只看主記憶或某個服務的記憶。它們和主工作階段記憶一樣會被召回，但不會讓主工作階段的記憶失效；刪除對話不會刪除它們，要在對外服務頁刪除服務時勾選「同時刪除它寫入的記憶」。

## 維護與設定

- 宿主每天跑一次維護：先確保記憶庫有 24 小時內的備份（`memory/backups/`，保留最近 7 份），再升級、降級、清理過期、壓縮。啟動時若最新備份已過期也會補一份。單次失敗只記錄，下次重試。
- `memory.embeddings`：本機 n-gram 雜湊向量，預設關閉，無外部相依。改動在下次開啟記憶庫時生效。

## 儲存

`<workspace>/memory/memory.db` 是主庫；`memory/backups/` 保留最近 7 份每日備份。刪除主庫只會遺失上次備份之後的寫入。
