# 記憶

返回 [文件目錄](./README.zh-TW.md)。

例如，你曾提過「我用的是公司內網帳號 alice」，之後換個方式詢問時，系統仍能找回這項資訊。記憶儲存在本機 SQLite 資料庫，每筆都能檢視、修改或刪除。

## 運作方式

| 階段 | 處理方式 |
|---|---|
| 寫入 | 從使用者原話自動提煉；排程輪次和助手執行後的複述不會自動成為通用記憶 |
| 召回 | 每輪請求前搜尋相關記錄，將它們作為背景放在目前使用者訊息之前；用量受設定上限和剩餘上下文空間限制，不會擠掉已選歷史 |
| 時效 | 每筆注入資料附有層級和時間，例如 `[established, 10 天前]`，並提醒模型以你現在提供的資訊為準 |
| 中文搜尋 | 使用獨立的 bigram 全文索引，不需要掃描整張資料表 |

子 agent 的回報不會儲存為記憶。

遇到缺少明確對象的短指代時，可以用目前可見對話中最近的使用者文字補充候選搜尋，但不會取代原始查詢。錯誤碼、檔名等明確識別碼若完整相符，可獲得有限加分，原因會記錄在 `reasons`。管理端點 `POST /api/memory/recall` 只搜尋提交的 `query`，不會加入對話上下文，也不使用對外服務的來源排除或注入預算。

滾動摘要、背景召回和原文讀取各自處理不同需求。壓縮會把舊對話折疊成滾動摘要，但摘要裡的事實不會自動寫入長期記憶。每輪背景召回則從 SQLite 選出相關記錄。主 agent 也能按需透過 `session_history` 搜尋目前工作區歷史，或按 `Seq` 分頁讀取原文；原文不會自動注入。搜尋和讀取可以看到被壓縮隱藏的原文及其最新修訂，但不會顯示其他已撤回內容。實體刪除（`purge`）後便不能讀取，也無法從摘要或備份還原。工具結果只包含實際寫入的文字，寫入前已截斷的部分無法取回。

`session_history` 的 `day` 可接受 `YYYY-MM-DD`、`today` 或 `yesterday`，依執行主機的本地時區及原始事件時間篩選，也可以搭配 `query`。回傳結果包含絕對日期，最多 8 筆。續頁時使用回傳日期、原本的 `query` 和排他的 `beforeSeq`；正文可用 `seq` / `offset` 接續讀取。指定日期沒有結果時不會改查其他日期。

相關性時效依來源記錄時間計算，重複召回不會讓舊事實變新。Working 記錄和可搜尋的晉升副本不會同時佔用檢索候選名額，但管理清單仍會顯示兩者。

## 四個層級

介面上的名稱為：**剛記下 / 經歷 / 事實 / 做法**。

- 文字相似，或層級和來源相同，都不能證明兩筆記錄是同一項事實，因此不會自動讓舊記錄失效；明確修訂仍可取代舊記錄。
- 三個月未被召回的記錄會降一級，之後由定期清理移除。
- 可在記憶頁手動調整層級。哪些事實是你會依賴的，由你判斷。

## 記憶頁功能

- 檢視所有記錄，包括已失效內容、取代它的記錄，以及上次使用時間。
- 依層級篩選，並查看每層筆數。
- **固定**：固定的記錄不會自動降級或清理，但仍可由明確修訂取代。
- **新建**：手動新增一筆記憶，預設放在「事實」層，長度限制為 4–400 字。
- 刪除單筆記錄。

## 刪除對話的影響

刪除或撤回一段對話時，從該段對話提煉出的記憶也會一併刪除。手動建立的記憶沒有隸屬於任何回合，因此不受影響。

## 對外服務寫入的記憶

[對外服務](./services.zh-TW.md)會把遊戲 mod、外掛等外部程式的互動整理成一句話，寫入主記憶；來源標籤以 `[对外服务:<名稱>]` 開頭。記憶頁會標示服務來源，也能只查看主記憶或特定服務的資料。這些記錄和主工作階段記憶一樣會被召回，但不會使主工作階段記憶失效；刪除對話也不會刪掉它們。若要清除，請在對外服務頁刪除服務時勾選「同時刪除它寫入的記憶」。

## 維護與設定

- 宿主每天執行一次維護：先確保 `memory/backups/` 內有一份 24 小時內的資料庫備份（保留最新 7 份），再進行升級、降級、過期清理和壓縮。若啟動時最新備份已過期，也會補做備份。單次失敗只會記錄日誌，下次再試。
- `memory.embeddings` 使用本機 n-gram 雜湊向量，預設關閉，沒有外部相依套件；重新開啟記憶庫時才會套用變更。

## 儲存

主資料庫位於 `<workspace>/memory/memory.db`；`memory/backups/` 保留最近 7 份每日備份。刪除主庫會遺失上次備份後新增的資料。
