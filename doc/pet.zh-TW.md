# 桌寵

[简体中文](./pet.md) | **繁體中文** | [English](./pet.en.md)

返回 [文件目錄](./README.zh-TW.md)。

一個常駐桌面的 Live2D 角色：它不參與對話，只讀取同一條工作階段記錄裡**已經定稿**的助手回覆，依關鍵詞判斷情緒，再用固定場景表播動作和表情。不改系統提示，不要求模型輸出情緒標籤，也不新增任何模型請求。

## 1. 它是什麼

- **一個獨立的小視窗**：透明、無邊框、置頂、不進工作列、不能縮放。預設 300×360，模型載入後依模型畫布尺寸 × 縮放比例自動調整。
- **只讀工作階段**：每 1 秒（說話時每 250 ms）輪詢 `GET /api/pet/feed`，取得 `seq` 之後的新回覆。歷史回覆不會補演，所以剛打開桌寵時它不會一連串地演過去。
- **不看串流內容**：只有助手已經定稿的回覆參與比對，正在串流輸出的那半句不算。
- **和你共用設定**：縮放、待機間隔、睡眠分鐘數、問候時間、情緒冷卻、表情保持、動作對應、關鍵詞字典都在「設定 → 桌寵」裡；儲存後桌寵視窗即時更新，不用重啟。
- **不做的事**：不彈氣泡、不搭話、不送出任何請求給模型。

## 2. 安裝 Cubism Core

Core 是 Live2D 的執行環境，**不隨應用程式分發**，必須由你從 Live2D 官網自行下載並同意其協議。儲存庫和安裝包都不含它，也不提供鏡像。

只認 **Cubism 5 SDK for Web R5**，檔名為 `CubismSdkForWeb-5-r.5.zip`。舊版 Core 與 easy-live2d 1.x 不相容，所以匯入時嚴格校驗：

| 檢查項 | 要求 |
|---|---|
| 整包 SHA-256 | `67064a7fb1812cf502f5c4a03bfe12cc638c75a621bb4acf06bb28763df06ba0` |
| 取出的檔案 | 壓縮檔裡以 `/Core/live2dcubismcore.min.js` 和 `/Core/LICENSE.md` 結尾的兩個項目 |

SDK 頂層目錄名不固定，依項目後綴比對，不依完整路徑。雜湊不符直接拒絕，避免舊版 Core 或改過的腳本進入頁面的 `script-src`。

1. 在「設定 → 桌寵 → Cubism Core」點官網下載連結，自行下載 R5 的 zip。
2. 勾選「我已從 Live2D 官網下載並同意其協議」，否則匯入按鈕不可用。
3. 填 zip 的絕對路徑，按「匯入」。
4. 成功後頁面顯示「已安裝 R5」和雜湊前 8 位。

檔案落在 `%LOCALAPPDATA%\Partner\pet\core\`，模型落在 `%LOCALAPPDATA%\Partner\pet\models\<id>\`。模型 id 是目錄名的 ASCII 化基名加上檔案內容雜湊的前 8 位，所以同一份模型重複匯入不會產生第二份。

## 3. 匯入模型

模型**不隨應用程式分發**，版權屬於各自的作者。你可以匯入目錄，也可以匯入 zip。

- **路徑**：目錄或 zip 都可以；zip 裡的中文檔名沒有設 UTF-8 旗標時依 GBK 解碼，所以舊包也能讀。
- **多個 model3**：一個包裡有不只一個 `*.model3.json` 時，頁面會列出候選（相對路徑），讓你挑一個；只有一個時直接匯入。
- **只複製被引用的檔案**：`model3.json` 的 `FileReferences` 裡列出的 moc3、貼圖、物理、姿態、表情、動作和音效才複製，同目錄下沒被引用的貼圖和 `exp_*.json` 不會跟著進來。
- **校驗**：路徑必須是相對路徑、不能含 `..`、正規化後要落在模型根目錄內、不能是符號連結或 junction；副檔名只允許 `.json .moc3 .png .jpg .webp .wav .mp3 .ogg .flac`（不接收 `.js`）；總量 200 MB、檔案數 2000 為上限。
- **重複匯入**：內容沒變就回傳已有的那一筆，不佔第二份空間。
- 「已匯入」列表顯示名稱（目錄名）、動作數、表情數、有無點擊區域、佔用大小；可以設為目前、刪除，也可以刪除目前模型（刪除後桌寵不顯示，直到再選一個）。

模型沒有 `HitAreas` 時，頭部和臉部的點擊分區依模型包圍盒的縱向比例切分，比例在「動作對應」頁籤裡用滑桿調。

視窗會裁到人物本身的不透明範圍，而不是整張模型畫布。模型畫布通常留了很大空白（實測一個模型的人物只佔畫布的 44%×47%），直接照畫布開窗會讓桌寵看起來很小，依畫布高度算的分區比例也會落在空白上。所以載入後先渲染一幀、讀回 alpha 通道量出人物的盒子，視窗就照這個盒子開，`100%` 指的是人物 360 邏輯像素高。

## 4. 場景

場景是固定的，觸發只有兩類：本機互動 / 計時，以及回覆文本的關鍵詞比對。每個場景由「動作組合 + 表情」組成，動作先依目前模型的對應表解析，對應不到就退到程序化參數軌道，參數也不存在就跳過。

| 場景 | 觸發條件 | 動作組合 / 表情 | 優先順序 |
|---|---|---|---|
| 首次載入 | 模型就緒之後 | 打招呼 + 眨眼 / 笑 | 2 |
| 靜默 | 沒有其他場景執行 | 常駐微動作 / 預設 | 0 |
| 待機 | 靜默持續 `rand(IdleMin, IdleMax)` 秒 | 打招呼 45%、伸懶腰 45%、眨眼 10% → 回到靜默 | 1 |
| 點擊頭部 | 單擊，落在頭部 | 模型自帶 `TapHead`/`Tap` 組時優先播它；否則三選一：摸頭反應 / 歪頭 / 左右晃動頭部。表情二選一：害羞 / 怒 | 4 |
| 點擊臉部 | 單擊，落在臉部 | 模型自帶 `TapFace`/`TapHead`/`Tap` 時優先播它；否則眨眼 + 輕微後仰。表情：笑或害羞 | 4 |
| 點擊身體 | 單擊，落在身體 | 模型自帶 `TapBody`/`Tap` 時優先播它；否則左右晃動身體或縮身。表情：害羞或怒 | 4 |
| 滑鼠懸停 | 懸停 600 ms | 視線跟隨常開；本場景只加一次輕微歪頭 / 預設 | 疊加層 |
| 拖曳模型 | 拖曳開始 | 拖曳回彈（隨速度）/ 預設；速度過閾值改為驚訝 | 5 |
| 快速拖曳後放開 | 放開速度超過閾值 | 左右晃動頭部 + 左右晃動身體 + 回彈 / 驚訝 | 5 |
| 雙擊模型 | 雙擊 | 打招呼 + 揮手 / 笑 | 4 |
| 語音或 TTS | 正在朗讀或說話 | 嘴型同步 + 每 3–5 s 輕微點頭 / 目前情緒表情或笑 | 疊加層 |
| 定時問候 | 本機時間到問候時間之一（每天每項一次；睡眠中先喚醒） | 打招呼 + 揮手 / 笑 | 2 |
| 閒置逾時 | 無互動、無新回覆達 `SleepAfterMinutes` | 伸懶腰 → 睡眠 / 預設或睏 | 1 |
| 睡眠中點擊 | 睡眠狀態下的任意點擊 | 先喚醒（眨眼 + 睜眼），再播該點擊本身的場景 | 4 |
| 情緒：笑 / 怒 / 哭 / 害羞 | 回覆比對結果，或設定頁的預覽按鈕 | 揮手或點頭 / 鼓臉 / 抽泣 / 歪頭或縮身；表情對應 | 3 |

規則細節：

- 新場景的優先順序要 **≥** 目前主場景才能搶佔，否則丟棄；情緒場景例外，會排隊一條，等目前場景結束再執行。
- 情緒場景有冷卻（`EmotionCooldownSeconds`）；同一情緒連續觸發只刷新表情保持時間，不重播動作。
- 睡眠中只有點擊能喚醒；喚醒先播喚醒場景，再播這次點擊自己的場景（第一次點擊不會「沒反應」）。新回覆和定時問候會先喚醒再執行原場景；拖曳照常執行但不喚醒。
- 睡眠中只有眼球跟隨游標，頭部不動，說話時也不點頭——睡姿由 `sleep` 軌道保持，別的寫入會和它打架。
- 表情在 `ExpressionHoldSeconds` 後回到預設。
- 待機、問候、冷卻的隨機源和時鐘都是注入的，所以測試能固定它們。

## 5. 情緒關鍵詞字典

「設定 → 桌寵 → 情緒字典」裡四種情緒各有一張可編輯表，另有否定前綴、最低權重和「恢復預設」。同一個 `emotion.ts` 既給桌寵打分，也給頁籤裡的試算框打分，所以試算結果就是真實結果。

比對規則：

1. 前處理：去掉程式碼區塊、行內程式碼、URL 和 Markdown 連結目標；英文轉小寫；最多取 4000 字。
2. 關鍵詞依長度遞減查找，已被更長關鍵詞佔用的區間不再重複計算——所以「不開心」不會同時命中「開心」。英文要求單詞邊界，中文和 emoji 依子字串比對。
3. 命中位置前 2 個字元內出現否定前綴（`不 沒 別 不太 並不 not no never`），且「否定詞 + 關鍵詞」本身不在字典裡時，這次命中作廢。
4. 每種情緒取**命中關鍵詞裡的最高權重**作為主分，主分最高的情緒勝出；主分相同比該情緒命中權重總和；仍相同取最後出現位置更靠後的那個。
5. 主分低於 `MinWeight` 或者沒有命中，就不觸發。

預設字典（權重 1–5；可在頁籤裡增刪改）：

| 情緒 | 關鍵詞（權重） |
|---|---|
| 笑 | 哈哈(3) 嘻嘻(3) 好笑(3) 開心(3) 高興(3) 太好了(4) 恭喜(4) 棒(2) 不錯(1) 喜歡(2) 有趣(2) 😄(4) 😊(3) 🎉(4) haha(3) great(2) awesome(3) glad(2) |
| 怒 | 生氣(4) 氣死(5) 可惡(4) 討厭(3) 煩(2) 不能接受(3) 過分(3) 哼(3) 😠(4) 😡(5) angry(4) annoying(3) |
| 哭 | 難過(4) 傷心(4) 哭(4) 嗚嗚(4) 抱歉(2) 遺憾(3) 可惜(2) 不開心(3) 失敗(2) 😢(4) 😭(5) sorry(2) sad(4) unfortunately(2) |
| 害羞 | 害羞(4) 不好意思(3) 臉紅(4) 過獎(3) 哪裡哪裡(3) 被誇(3) 討厭啦(4) ///(3) 😳(4) ☺️(3) blush(4) flattered(3) |

`討厭啦`（害羞）比 `討厭`（怒）長，依最長比對優先，所以不會被算成怒。

例：「哈哈，這個太好笑了，不過被你誇得有點害羞」→ 笑 {哈哈 3, 好笑 3}，主分 3；害羞 {害羞 4}，主分 4 → 觸發「情緒：害羞」。

## 7. 已知限制

- **嘴型沒有音訊**：TTS 在 .NET 側用 NAudio 播放，WebView 拿不到音訊流，所以嘴型是「說話時依 6–9 Hz 的隨機包絡張合」，不是真實音素。`speaking` 由後端依播放狀態回報，只能說明在說話，不能說明說到哪個字。
- **動作靠程序化兜底**：不能假設模型自帶需要的動作和點擊區域。範例模型只帶兩個動作組、沒有 `Idle` 組、沒有 `HitAreas`、物理和姿態也沒有，所以很多場景落到參數關鍵影格上（`ParamAngleX/Y/Z`、`ParamBodyAngle*`、`ParamEye*`、`ParamMouthForm` 等）。模型沒有那個參數就跳過這一段，不會報錯也不會硬插。動作對應在「動作對應」頁籤裡可以逐項指定，指定「自動」才依名字猜。
- **release 建置沒有桌寵**：原因見上一節，不是 bug。
- **沒有聲音聯動**：動作音效預設關閉，可在設定裡打開；開啟時遵循 `Config.MotionSound`。
- **視窗能力有限**：桌寵視窗只拿到移動、改尺寸、讀游標、滑鼠穿透這幾個權限，不能關閉自己、不能開機自啟。關閉主視窗或在系統匣裡選「結束」會一起結束。
- **單螢幕和多螢幕**：位置依 `pet-window.json` 還原，落在可見區域外就挪回主螢幕右下角。125% / 150% 縮放和負座標副螢幕的手動冒煙還在補。
- **透明區域穿透**：每 50 ms 讀一次游標下的像素 alpha 決定是否穿透；拖曳期間強制不穿透。沒有設 `premultipliedAlpha` 的模型可能邊緣發暗。
- **效能**：30 fps 上限，視窗隱藏時停 ticker。模型很重時（多張大貼圖）拖曳會掉格。
