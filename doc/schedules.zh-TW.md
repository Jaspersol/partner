# 定時

[简体中文](./schedules.md) | **繁體中文** | [English](./schedules.en.md)

返回 [文件目錄](./README.zh-TW.md)。

一個定時任務由一句內容和一條觸發規則組成。時間到達後，這句話會以「排程」來源加入佇列，與打字和語音輸入一樣依序執行。

排程輪次不會自動寫入通用記憶，也不會自動附帶主工作階段摘要、其他任務輪次或一般召回；需要時仍可自行回讀執行過程。任務完成不表示業務檢查一定成功。

主 agent 直接呼叫 `web_fetch` 時，若是沒有重新導向且沒有讀取錯誤的 HTTP(S) GET，可以記錄不含憑證與查詢參數之目標的狀態碼：5xx 會替該任務開啟異常，之後同一目標回傳 2xx 時關閉異常。系統只保存規範化 URI 的雜湊，不保存額外 URL 或正文；這只代表當次觀察到的 HTTP 狀態，不代表網頁內容或整個服務健康。一般完成、其他目標的成功、委派結果和使用者自由文字都不能關閉異常。同一批並行檢查若對同一目標同時回傳 5xx 和 2xx，該目標狀態不會更新。

投影最多顯示該任務一個未解決的結構化異常及其來源 `Seq`。沒有這類異常時，會顯示最近的普通工具失敗線索，但它不代表業務狀態。撤回或刪除證據後，系統會按剩餘可見證據重新計算，因此撤回解決證據可能再次顯示較舊的異常。重查必須依目前指令實際執行，舊線索不能代替本輪結果。

## 規則

| 類型 | 寫法 | 說明 |
|---|---|---|
| `cron` | 五段 cron | 使用本機時區 |
| `interval` | 分鐘數，≥ 1 | 從建立時開始計算 |
| `once` | 一個時間點 | 必須晚於現在，執行後標記為已執行 |

限制：內容最多 2000 字，間隔可從 1 分鐘到 1 年，最多建立 100 個任務。

## 在頁面上管理

側邊欄的 **定時** 頁面可用來：

- 新建：選擇規則並填寫內容。日期時間選擇器提供「1 小時後 / 明天 9:00 / 下週一 9:00」等快捷選項，不能選擇過去的時間。
- 暫停 / 恢復：恢復時會跳過暫停期間錯過的時間點，不會補發；應用程式關閉期間錯過的時間也會跳過。
- 刪除。

目前沒有「編輯」。要修改規則或內容，請刪除後重新建立，避免舊的發放記錄吞掉新的觸發。

## 讓助手建立任務

主 agent 一直擁有 `schedule_create`、`schedule_list` 和 `schedule_delete` 三個工具，子 agent 沒有。

- 工具結果包含目前本機時間，因此一次性任務可以直接寫「幾分鐘後」。
- 審批依輸入區檔位處理：「危險指令審批」只詢問刪除；「全部審批」會詢問建立和刪除；列出任務永遠不詢問。
- 原因是任務內容到時間會被當成你發出的訊息，不能讓助手讀到的網頁偷偷替你建立任務。

## 儲存

任務與發放收據以附加方式分別寫入 `<workspace>/scheduler/tasks.jsonl` 和 `receipts.jsonl`。
