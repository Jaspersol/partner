# 子 agent

[简体中文](./sub-agents.md) | **繁體中文** | [English](./sub-agents.en.md)

返回 [文件目錄](./README.zh-TW.md)。

主 agent 只對話和派工。點視窗、讀檔案這類耗時的工作交給子 agent 在背景做，做完把結果當成一條新輸入回報，主 agent 再轉述給你。

## 場景

場景固定兩項，每個場景最多一個子 agent：

| 場景 | 子 agent 的工具 | 開關 | 由誰佔用 |
|---|---|---|---|
| `desktop` 桌面操控 | `desktop_*` | `desktop.enabled` | 內建「桌面操控」子 agent，不可刪 |
| `file-read` 檔案存取 | `file_list`、`file_read`；符合寫入條件時另有 `file_write`、`file_edit`（編輯須支援 NTFS 交易） | `files.enabled` + 讀取白名單；寫入另需 `files.writeEnabled` + 寫入白名單（皆預設關閉） | 使用者自行新增 |

- 沒人佔用的場景由主 agent 自己執行。例如開了讀檔但沒建讀檔子 agent，`file_*` 工具就給主 agent。
- 桌面例外：桌面工具從不給主 agent。開啟桌面就必須有啟用的桌面子 agent，儲存時會檢查。

## 派工與回報

- 主 agent 有三個工具：`agent_delegate`（立即返回）、`agent_job_status`、`agent_job_cancel`。
- 任務在背景跑，不佔主對話。結束後回報進入同一條佇列，主 agent 開新的一輪來轉述。
- 每個任務有自己的工作階段記錄（`agents/<agent>/job-*/session/`）；每個 agent 只保留最近 30 個任務。截圖和讀到的檔案內容不進主工作階段，也不進記憶。
- 一個子 agent 同時只跑一個任務。同一目標剛失敗，10 分鐘內不能原樣再派。
- 行程當掉後，沒結束的任務會在下次啟動時補一條「已中斷」的回報。

## 重試與失敗

- 每個任務最多跑 `maxRounds` 輪，預設 5（可調 1–10）。總時限 15 分鐘。
- 成敗由子 agent 呼叫 `task_report` 判定：成功要帶證據，失敗要帶錯誤。沒呼叫就算失敗。
- 審批被拒、治理拒絕、取消、逾時等終止類失敗不重試。其餘失敗重試前，會把上一輪已執行的動作告訴子 agent，要求先看現狀。
- 全部失敗時，主 agent 收到原因類別、最後一次錯誤和逐輪記錄，並被要求如實轉告，不能說成功。

## 提示詞與模型

在「設定 → agent」頁編輯：

- 主 agent 和每個子 agent 都有可編輯的提示詞。沒改過就用內建預設，升級後自動拿到新預設。
- 結尾自動產生的檔案工具邊界、「可委派場景」和「回報方式」不可編輯；文字與語音請求遵循相同邊界。
- 改提示詞不重啟消費者，下一輪生效。
- 子 agent 的模型預設跟隨主模型，也可以單獨設定，例如桌面子 agent 用視覺模型。

## 檔案存取的邊界

- 原生檔案工具支援列出目錄、讀取，以及符合條件時新建和編輯檔案。直接檔案請求必須使用相應原生工具；未呼叫、不可用、遭拒或失敗時，不應聲稱成功或改走桌面、指令或 MCP。使用者明確要求透過特定應用程式辦理的桌面任務除外。
- `files.writeEnabled` 預設關閉，`files.writeRoots` 預設為空；舊設定不會自動取得寫入權限。啟用時須設定至少一個已存在的絕對目錄。`file_write` 僅支援 Windows 本機 NTFS，目標須同時位於讀取與寫入白名單，且每次明確批准；只新建，不覆蓋既有檔案或編輯原件。
- 新建要求父目錄已存在，不會建立目錄；不支援網路磁碟、特殊路徑或重新剖析點，並拒絕 Partner 資料及憑證路徑。檔案使用無 BOM 的 UTF-8。建立失敗或結果未確認時，不應聲稱成功或自動重試；先檢查目標與權限，再決定如何處理。
- `file_edit` 遵循相同的白名單與單次審批規則，依 `file_read` 回傳的 SHA-256 版本精確替換唯一相符的 UTF-8 文字。編輯只寫入原檔案物件的預設資料流，保留 BOM、安全描述元及替代資料流；成品上限為 8 MiB。僅在支援 Windows [NTFS 交易（TxF）](https://learn.microsoft.com/en-us/windows/win32/fileio/transactional-ntfs-portal) 的本機磁碟區執行。提交時在交易鎖內重新檢查版本和硬連結；版本變更、存在多個硬連結、交易不可用或不支援目標時拒絕，不退回非交易寫入。
- 這是給 agent 的提示約定，不是系統沙箱：桌面應用程式、指令和 MCP 依系統權限存取檔案，不繼承檔案白名單；MCP 免審批清單也不是檔案授權。需要系統級隔離時應使用系統安全措施。
- 路徑必須在 `files.roots` 內。`..` 穿越和指向目錄外的連結都拒絕。
- Windows 與 Linux 上讀取和目錄列舉會檢查已開啟控制代碼的實際路徑；無法驗證的平台會遭拒。Windows 拒絕替代資料流；硬連結別名仍無法據此辨識為受保護檔案，白名單不是檔案系統沙箱。
- `file_list` 依目錄優先、名稱不分大小寫排序（大小寫相同的排序位置再依序數字元排序），預設從 `offset: 0` 回傳最多 200 項；可指定非負整數 `offset` 和 1–200 的 `limit`，有後續項時以回傳的下一頁 offset 繼續，並保持相同的 `path` 和 `limit`。每次呼叫重新列舉目錄，並非快照：新增、刪除或重新命名可能使翻頁重複或遺漏，目錄變動時應從頭重列。
- 只讀文字，分段讀取，單段預設 12000、上限 40000 字元；二進位檔和超過 8 MB 的檔案拒絕。
- `file_read` 的 offset 和 limit 以 UTF-16 程式碼單元計數；不會拆開代理對，若 limit 太小或 offset 位於代理對中間會回傳參數錯誤。
- 單頁超過上下文結果預算時不會回傳不完整頁面；請保持路徑和 offset，縮小 limit 後重試。
- 每次讀取回傳所讀位元組的 SHA-256 版本；分頁之間檔案可能改變，應比較版本。版本不是檔案鎖，也不保證後續讀取一致。
- 目錄內也不讀 `.env*`、`*.pem`、`*.key`、`*.pfx` 等金鑰檔，以及整個工作區。
- 讀到的內容會進模型上下文，白名單別設得太寬。
