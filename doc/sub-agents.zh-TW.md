# 子 agent

[简体中文](./sub-agents.md) | **繁體中文** | [English](./sub-agents.en.md)

返回 [文件目錄](./README.zh-TW.md)。

主 agent 負責對話與派工。操作視窗、讀取檔案等耗時工作交由子 agent 在背景執行；完成後，子 agent 會把結果當成新的輸入回報，再由主 agent 轉述。

## 場景

場景固定為兩類，每類最多指派一個子 agent：

| 場景 | 可用工具 | 開關 | 負責者 |
|---|---|---|---|
| `desktop` 桌面操控 | `desktop_*` | `desktop.enabled` | 內建「桌面操控」子 agent，不可刪除 |
| `file-read` 檔案存取 | `file_list`、`file_read`；符合寫入條件時另有 `file_write`、`file_edit`（編輯須支援 NTFS 交易） | `files.enabled` + 讀取白名單；寫入另需 `files.writeEnabled` + 寫入白名單（兩者預設關閉） | 使用者自行新增 |

- 沒有子 agent 負責的場景由主 agent 處理。例如開啟檔案讀取但沒有建立讀檔子 agent 時，`file_*` 工具會交給主 agent。
- 桌面操控是例外：桌面工具絕不會交給主 agent。啟用桌面操控必須同時啟用桌面子 agent，儲存時會檢查這項條件。

## 派工與回報

- 主 agent 可使用 `agent_delegate`（立即返回）、`agent_job_status` 和 `agent_job_cancel` 三項工具。
- 任務在背景執行，不會佔住主對話。完成後的回報進入同一條佇列，主 agent 另開一輪轉述結果。
- 每項工作都有自己的工作階段記錄，位於 `agents/<agent>/job-*/session/`；每個 agent 只保留最新 30 項任務。截圖和讀取的檔案內容不會進入主工作階段或記憶。
- 每個子 agent 同時只能執行一項任務。同一目標剛失敗後，10 分鐘內不能原樣再派一次。
- 行程當掉後，未完成的任務會在下次啟動時收到一筆「已中斷」回報。

## 重試與失敗

- 每項任務最多執行 `maxRounds` 輪，預設為 5（可設為 1–10），總時限 15 分鐘。
- 子 agent 呼叫 `task_report` 判定成功或失敗：成功需附證據，失敗需提供錯誤；未呼叫即視為失敗。
- 審批遭拒、治理拒絕、取消或逾時等終止類失敗不重試。其他失敗在重試前，會把上一輪已執行的動作告知子 agent，並要求先檢查目前狀態。
- 所有輪次都失敗時，主 agent 會收到原因類別、最後錯誤和各輪記錄，並被要求如實轉告，不能宣稱成功。

## 提示詞與模型

在「設定 → agent」頁進行編輯：

- 主 agent 和每個子 agent 都有可修改的提示詞。沒有自訂時使用內建預設，程式升級後會取得新版預設內容。
- 系統自動附加的檔案工具界線、「可委派場景」和「回報方式」無法編輯；文字與語音請求都受相同界線約束。
- 修改提示詞不必重啟消費者，下個回合就會套用。
- 子 agent 預設跟隨主模型，也可另外指定，例如為桌面子 agent 選擇視覺模型。

## 檔案存取界線

- 原生檔案工具可列出目錄、讀取檔案，並在符合條件時建立或編輯檔案。直接處理檔案的請求必須使用相應原生工具。工具未呼叫、不可用、遭拒或失敗時，不可宣稱已完成，也不可改走桌面、指令或 MCP 繞過限制；使用者明確要求透過某個應用程式辦理的桌面任務除外。
- `files.writeEnabled` 預設關閉，`files.writeRoots` 預設為空；舊設定不會自動取得寫入權限。啟用後至少要設定一個已存在的絕對路徑。`file_write` 僅支援 Windows 本機 NTFS，目標必須同時位於讀取與寫入白名單中。「不審批」檔位下直接執行，其餘檔位每次都要明確批准。此工具只建立新檔，不會覆蓋或編輯現有檔案。
- 新檔案的父目錄必須已存在，工具不會建立目錄。不支援網路磁碟、特殊路徑、重新剖析點，也會拒絕 Partner 資料與憑證路徑。輸出檔為無 BOM 的 UTF-8。若建立失敗或結果未確認，不應聲稱成功或自動重試；先檢查目標和權限，再決定如何處理。
- `file_edit` 使用相同白名單和審批規則，依 `file_read` 回傳的 SHA-256 版本精確替換唯一相符的 UTF-8 內容。它只寫入原檔案物件的預設資料流，同時保留 BOM、安全描述元和替代資料流；完成後檔案上限為 8 MiB。僅能在支援 Windows [NTFS 交易（TxF）](https://learn.microsoft.com/en-us/windows/win32/fileio/transactional-ntfs-portal) 的本機磁碟區執行。提交時會在交易鎖內再次確認版本與硬連結；版本已變、多個硬連結、交易不可用或目標不支援時一律拒絕，不會改用非交易方式寫入。
- 以上是 agent 的提示規則，不是系統沙箱。桌面應用程式、指令和 MCP 依系統權限存取檔案，不受檔案白名單限制；MCP 免審批清單也不等於檔案授權。需要系統級隔離時應採用系統安全措施。
- 路徑必須在 `files.roots` 範圍內。`..` 穿越和指向目錄外部的連結都會遭拒。
- Windows 與 Linux 的讀取和目錄列舉會檢查已開啟控制代碼的實際路徑；無法驗證的平台會拒絕操作。Windows 不允許替代資料流。這項檢查仍無法辨識指向受保護檔案的硬連結別名，因此白名單並非檔案系統沙箱。
- `file_list` 先列目錄，再依不區分大小寫的名稱排序；只有大小寫不同的名稱會以序數字元順序決定先後。預設從 `offset: 0` 開始，最多傳回 200 項。可指定非負整數 `offset` 與 1–200 的 `limit`；若還有下一頁，使用回傳的 offset，並沿用相同 `path` 和 `limit`。每次呼叫都會重新列舉目錄，不是快照；新增、刪除或重新命名可能導致重複或遺漏，目錄變更後應從頭列舉。
- 只讀取文字，分段回傳；每段預設 12000 字元，最多 40000 字元。二進位檔案和超過 8 MB 的檔案會被拒絕。
- `file_read` 的 offset 和 limit 以 UTF-16 程式碼單元計算，不會切開代理對。若 limit 太小或 offset 位於代理對中間，會回傳參數錯誤。
- 單頁結果超過上下文預算時，不會回傳不完整頁面；保留路徑和 offset，縮小 limit 後再試。
- 每次讀取都會回傳所讀位元組的 SHA-256 版本。檔案在分頁期間可能改變，應比較版本；它不是檔案鎖，也不保證後續讀取一致。
- 即使在允許目錄中，也不會讀取 `.env*`、`*.pem`、`*.key`、`*.pfx` 等金鑰檔，也不會讀取整個工作區。
- 讀取的內容會放入模型上下文，因此白名單應設定得精簡。
