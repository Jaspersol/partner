# 對外記憶服務（Memory Service）

[简体中文](./services.md) | **繁體中文** | [English](./services.en.md)

返回 [文件目錄](./README.zh-TW.md)。

「對外記憶服務」把應用程式變成可託管多個反向代理執行個體的宿主：每個執行個體佔用一個獨立的 `127.0.0.1` 埠，透傳上游 OpenAI 或 Anthropic 模型，在請求中注入主記憶召回，可選地在請求前加一段自訂提示詞，並按設定的時間把本服務期間的互動總結成一句話，寫回主記憶庫。

## 它是什麼

- 每個執行個體是一個反向代理：把用戶端的認證換成上游 Key、把對外模型名替換成上游模型名，其餘照轉發。`tools`、`tool_choice`、`stream`、`response_format` 以及上游回傳的 `tool_calls`、SSE、`usage`、錯誤體都原樣透傳。
- 服務**沒有工作階段**：用戶端自己保存對話歷史（無狀態），每次請求帶完整歷史；服務端只在本機暫存待總結的輪次。
- 每次請求會檢索主記憶並注入到最後一條含文字的 user 訊息前面；可選自訂提示詞（留空則不改動請求）。
- 定時（或停機、刪除、手動「立即總結」時）把這一窗口的互動總結成一句話寫入主記憶庫，來源標記 `service:<id>`。
- 只監聽 `127.0.0.1`，不暴露到區域網路。對外暴露的模型名必須等於設定的模型名，否則回傳 404。

## 在介面裡建立服務

側邊欄 **服務（Services）** 頁：

1. 點「新增」，填寫下表欄位並儲存。儲存即啟動，執行個體監聽 `http://127.0.0.1:<port>/v1`。
2. 建立時服務端產生 ID 和權杖；**明文權杖只在建立（或輪換）時顯示一次**，請複製保存。
3. 卡片上能看到執行狀態與錯誤、請求數、待總結輪數、上次總結時間、最近寫入的記憶，並可直接跳轉記憶頁。
4. 卡片操作：立即總結、輪換權杖（明文只顯示一次）、刪除（對話框裡可選「同時刪除它寫入的記憶」）。
5. 改埠或協定會重建監聽，其餘欄位熱更新，下一個請求即生效。每個埠一個權杖。

## 欄位說明

| 欄位 | 說明 |
|---|---|
| 名稱 | 顯示名，也用於摘要的來源標籤 |
| 啟用 | 關閉即停止該執行個體 |
| 埠 | 1024–65535，各執行個體不能重複，也不能是主 API 埠 |
| 協定 | `openai` 或 `anthropic`。**必須與上游協定一致**：透傳不做協定轉換，不一致時儲存會被拒絕（已存在的設定在請求時回傳 502） |
| 模型名 | 對外暴露的模型名；請求裡的 `model` 必須等於它 |
| 上下文長度 | 用於計算召回注入的 token 預算，預設繼承主模型 |
| 自訂提示詞 | 可前置一段提示詞；留空則不改動請求 |
| 召回 | 開關、筆數上限、token 預算；關閉則不注入記憶 |
| 總結 | 開關、間隔（分鐘）、最長等待（分鐘）；關掉後不再寫回主記憶 |
| 上游 | 預設「繼承主模型」；也可自訂 baseUrl、模型名、API Key、最大輸出 tokens 和逾時 |
| 權杖 | 每個埠獨立；建立／輪換時只顯示一次明文 |

## 管理介面

管理端點掛在主 API 上，沿用啟動時的 Bearer 權杖：

- `GET /api/services`、`GET /api/services/{id}`：列出執行個體及其執行狀態。
- `POST /api/services`：建立，回應中**僅此一次**回傳明文權杖。
- `PUT /api/services/{id}`：修改（權杖、上游 Key 留空表示保留原值）。
- `DELETE /api/services/{id}?purgeMemories=false`：刪除；為 `true` 時同時軟刪除該服務寫入的記憶。
- `POST /api/services/{id}/flush`：立即總結，回傳寫入的記憶 ID。
- `POST /api/services/{id}/token`：輪換權杖，回傳一次明文。

## 呼叫範例

`model` 必須等於該服務設定的對外模型名。兩種認證頭對兩個協定都可用：`Authorization: Bearer <token>` 或 `x-api-key: <token>`。

OpenAI 協定（`POST /v1/chat/completions`，用 Bearer）：

```bash
curl http://127.0.0.1:<port>/v1/chat/completions -H "Authorization: Bearer <token>" -H "Content-Type: application/json" -d '{"model":"<model>","messages":[{"role":"user","content":"..."}]}'
```

Anthropic 協定（`POST /v1/messages`，用 `x-api-key`）：

```bash
curl http://127.0.0.1:<port>/v1/messages -H "x-api-key: <token>" -H "anthropic-version: 2023-06-01" -H "Content-Type: application/json" -d '{"model":"<model>","max_tokens":1024,"messages":[{"role":"user","content":"..."}]}'
```

列出可用模型（`GET /v1/models`）：

```bash
curl http://127.0.0.1:<port>/v1/models -H "Authorization: Bearer <token>"
```

串流（`stream: true`）、工具呼叫、`response_format` 等參數原樣透傳，SSE 逐幀回傳。

### 逾時與轉傳的回應標頭

- 等待上游回應標頭有時間上限（繼承主模型時用主模型的逾時，自訂上游時可個別設定）；逾時回傳 `504`，錯誤體依協定格式。拿到回應標頭之後，串流傳輸本身不再限時。非串流請求要等整個回覆產生完才有回應標頭，推理模型的長回覆可能因此逾時，這種情況請用 `stream: true`。
- 上游回傳的 `retry-after`、`x-ratelimit-*`、`anthropic-ratelimit-*`、`request-id`、`x-request-id`、`openai-processing-ms`、`cache-control` 原樣轉傳，方便 SDK 做退避重試；`set-cookie` 與框架類標頭（`content-length`、`transfer-encoding`、`connection`）不轉傳。

## 記憶歸屬與刪除

> **服務記憶寫入主記憶庫、主工作階段能召回；刪除對話不會刪除服務記憶，需要在服務頁刪除。** 服務把互動總結寫進主記憶庫（來源 `service:<id>`），主工作階段之後的回合會像一般記憶一樣召回它們。刪除或撤回主工作階段裡的對話**不會**連帶刪除這些記憶。

要清除這些記憶，請在「服務」頁刪除對應服務，並勾選「同時刪除它寫入的記憶」（相當於 `DELETE /api/services/{id}?purgeMemories=true`）；不勾選則保留。刪除服務時會先停止監聽（停止時會做最後一次總結），再刪除記憶，避免清除之後又有請求寫回一筆新的。

## 安全須知

- 外部內容會被總結後寫進主記憶，而主工作階段之後會召回這些摘要，因此存在**間接提示注入**風險：不可信的呼叫方可能藉摘要文字影響主 agent。只讓可信的用戶端存取服務埠，並定期查看寫入的摘要。
- 關閉總結：在「服務」頁把「總結」開關關掉（即 `Summary.Enabled=false`）。關閉後服務仍會注入記憶召回，但不再把互動寫回主記憶庫；已經寫入的記憶按上一節的方法手動刪除。
- 停機時所有執行個體並行做最後一次總結。如果有執行個體在上游逾時內沒答完，這一批會用模板句式直接寫入（不再等模型），不會因為退出而丟資料。
- 權杖不能為空：儲存時會自動為新增執行個體產生一個，驗證要求至少 32 個字元；空權杖的執行個體一律拒絕所有請求。
- 每個執行個體只監聽 `127.0.0.1`，不會暴露到區域網路；埠請求仍需帶該執行個體的權杖，管理端點沿用主 API 的啟動權杖。
