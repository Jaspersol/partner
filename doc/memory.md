# 记忆

**简体中文** | [繁體中文](./memory.zh-TW.md) | [English](./memory.en.md)

返回 [文档目录](./README.md)。

你说过“我用的是公司内网账号 alice”，下次换个说法问，它能想起来。记忆存在本地 SQLite，每一条都能看、能改、能删。

## 怎么工作

| 环节 | 做法 |
|---|---|
| 写入 | 从用户原话自动提炼；定时轮和助手执行复述不自动写入通用记忆 |
| 召回 | 每轮请求前检索相关记忆，在当前用户消息前注入背景；额度不超过配置上限和上下文剩余空间，不挤掉已选历史 |
| 时效 | 注入的每条带层级和时间，如 `[established, 10 天前]`，并提示模型以你现在说的为准 |
| 中文 | 单独建了 bigram 全文索引，中文检索不靠全表扫描 |

子 agent 的汇报不进记忆。

缺少明确对象的短指代可用当前可见对话中最近的用户文字补充候选查询，不替换原话；错误码、文件名等明确标识符的完整匹配可获得有限加分，原因写入 `reasons`。管理接口 `POST /api/memory/recall` 只检索提交的 `query`，不补对话上下文，也不使用对外服务的来源排除或注入预算。

滚动摘要、背景召回和原文回读各有用途：压缩把旧对话折叠为滚动摘要，摘要中的事实不会自动写入长期记忆；每轮背景召回从 SQLite 选相关记录。主 agent 也可按需用 `session_history` 搜索当前工作区的历史，或按 `Seq` 分页读取正文；它不会自动注入原文。搜索和读取可以看到压缩隐藏的原文及最新修订，但不会显示其他撤回的内容；物理删除（purge）后无法读取，也不会从摘要或备份恢复。工具结果只能回读实际入库的文本，入库前被截断的部分无法找回。

`session_history` 的 `day` 接受 `YYYY-MM-DD`、`today` 或 `yesterday`，按运行机器的本地时区及原始事件时间筛选，可结合 `query`；返回绝对日期和最多 8 条记录。续页使用返回的日期、原 `query` 和排他的 `beforeSeq`；正文可用 `seq` / `offset` 继续读取。没有结果不会回退到其他日期。

相关性时效按来源记录时间计算，重复召回不会让旧事实变新。Working 记录及其可检索的晋升副本不会同时挤占检索候选；管理列表仍保留两者。

## 四个层级

界面上显示为：**刚记下 / 经历 / 事实 / 做法**。

- 相似文字或同层同源不足以证明是同一事实，不自动使旧记录失效；明确修订仍可替换旧记录。
- 三个月没被召回的记录降一级，最后由定期清理移除。
- 层级可以在记忆页手动改。“这是我依赖的事实”只有你能判断。

## 在记忆页能做什么

- 查看全部记录，包括已失效的，以及“什么替换了它”“上次什么时候用过”。
- 按层筛选，每层显示计数。
- **固定**：固定的记录不会被自动降级或清理，但仍可明确修订。
- **新建**：手写一条记忆，默认落在“事实”层，长度 4–400 字。
- 删除单条记录。

## 和对话删除的关系

删除或撤回一段对话时，由这段对话提炼出的记忆一起删除。手写的记忆不属于任何一轮对话，不会跟着删。

## 对外服务写入的记忆

[对外服务](./services.md)会把游戏 mod、插件等外部程序的交互总结成一句话写进主记忆，以 `[对外服务:<名称>]` 开头。记忆页给这些记录标出来源服务，可以用「按来源筛选」只看主记忆或某个服务的记忆。它们和主会话记忆一样会被召回，但不会让主会话的记忆失效；删除对话不会删除它们，要在对外服务页删除服务时勾选「同时删除它写入的记忆」。

## 维护与设置

- 宿主每天跑一次维护：先确保记忆库有 24 小时内的备份（`memory/backups/`，保留最近 7 份），再升级、降级、清理过期、压缩。启动时若最新备份已过期也会补一份。单次失败只记日志，下次重试。
- `memory.embeddings`：本地 n-gram 哈希向量，默认关闭，无外部依赖。改动在下次打开记忆库时生效。

## 存储

`<workspace>/memory/memory.db` 是主库；`memory/backups/` 保存最近 7 份每日备份。删除主库只会丢失上次备份之后的写入。
