# 记忆

**简体中文** | [繁體中文](./memory.zh-TW.md) | [English](./memory.en.md)

例如，你曾提过“我用的是公司内网账号 alice”，之后换个方式询问时，系统仍可找回这条信息。记忆保存在本地 SQLite 数据库中，每条记录都能查看、修改或删除。

## 工作方式

| 环节 | 处理方式 |
|---|---|
| 写入 | 从用户原话自动提炼；定时轮和助手执行后的复述不会自动写成通用记忆 |
| 召回 | 每轮请求前搜索相关记忆，将它们作为背景放在当前用户消息前；用量受配置上限和剩余上下文空间约束，不会挤掉已选历史 |
| 时效 | 注入内容会带层级和时间，例如 `[established, 10 天前]`，并提醒模型以你当前的说法为准 |
| 中文检索 | 使用独立的 bigram 全文索引，不必扫描整张表 |

子 agent 的汇报不会写入记忆。

当简短指代没有明确对象时，候选检索可以参考当前可见对话中最近的用户文字，但不会替换原始查询。错误码、文件名等明确标识符的完整匹配可以获得有限加权，具体原因会写入 `reasons`。管理接口 `POST /api/memory/recall` 只搜索提交的 `query`，不会补充对话上下文，也不使用对外服务的来源排除或注入预算。

滚动摘要、背景召回和原文回读解决的是不同问题。压缩时，较早的对话会收进滚动摘要；摘要中的事实不会自动升级为长期记忆。每轮背景召回则从 SQLite 选择相关记录。主 agent 也可以按需用 `session_history` 搜索当前工作区历史，或按 `Seq` 分页读取原文；原文不会自动注入。搜索和读取能查看被压缩隐藏的原文及其最新修订，但不会显示其他已撤回内容。物理删除（purge）后无法读取，也不会从摘要或备份恢复。工具结果仅包含实际写入的文本，写入前被截断的部分无法找回。

`session_history` 的 `day` 可接受 `YYYY-MM-DD`、`today` 或 `yesterday`，依据运行机器本地时区和原始事件时间筛选，也可以附加 `query`。结果包含绝对日期，最多 8 条。继续翻页时使用返回的日期、原始 `query` 和排他的 `beforeSeq`；正文可通过 `seq` / `offset` 继续读取。指定日期没有结果时不会改查其他日期。

记忆时效按来源记录的时间计算，反复召回不会让旧事实变新。Working 记录及其可检索的晋升副本不会同时占用检索候选名额，但管理列表中仍会显示两者。

## 四个层级

界面名称为：**刚记下 / 经历 / 事实 / 做法**。

- 文本相似，或层级与来源相同，都不足以证明记录描述的是同一事实，因此不会自动让旧记录失效；明确的修订仍可替换旧记录。
- 三个月没有被召回的记录会下降一级，之后由定期清理移除。
- 记忆页允许手动调整层级。某条内容是否是你会依赖的事实，由你决定。

## 记忆页操作

- 查看所有记录，包括已失效的记录、替代它的内容以及最近一次使用时间。
- 按层级筛选，每一层都会显示计数。
- **固定**：被固定的记录不会自动降级或清理，但仍可由明确修订替换。
- **新建**：手动写入一条记忆，默认归入“事实”层，长度为 4–400 字。
- 删除单条记录。

## 对话删除的影响

删除或撤回一段对话时，从这段对话提炼出的记忆也会一并删除。手写记忆没有关联到任何对话，因此不会随对话删除。

## 对外服务写入的记忆

[对外服务](./services.md)会把游戏 mod、插件等外部程序中的交互归纳成一句话写入主记忆，来源标记以 `[对外服务:<名称>]` 开头。记忆页会显示相应服务来源，也能按来源只看主记忆或某个服务的记录。这些记忆和主会话记忆一样参与召回，但不会使主会话记忆失效；删除对话也不会删除它们。若要一并清除，请在对外服务页面删除服务时勾选“同时删除它写入的记忆”。

## 维护和设置

- 宿主每天执行一次维护：先确保记忆库有一份不超过 24 小时的备份（位于 `memory/backups/`，只保留最近 7 份），然后再升级、降级、清理过期记录和压缩。启动时如果最新备份已过期，也会补做备份。单次失败只写入日志，下次继续尝试。
- `memory.embeddings` 使用本地 n-gram 哈希向量，默认关闭，不依赖外部服务。修改后在下次打开记忆库时生效。

## 存储

主数据库位于 `<workspace>/memory/memory.db`；`memory/backups/` 保存最近 7 份每日备份。删除主库会丢失最近一次备份之后写入的内容。
