# 定时

**简体中文** | [繁體中文](./schedules.zh-TW.md) | [English](./schedules.en.md)

返回 [文档目录](./README.md)。

一个定时任务由一句内容和一个触发规则组成。规则到期后，内容会以“调度”来源进入队列，与键盘输入和语音输入一起按顺序处理。

定时轮次不会自动写入通用记忆，也不会自动带上主会话摘要、其他任务轮次或普通召回；需要时仍可自行回读执行过程。任务执行完成，也不能证明实际业务检查已经通过。

主 agent 直接调用 `web_fetch` 时，如果是没有跳转且没有读取错误的 HTTP(S) GET，可以记录不含凭据和查询参数的目标状态码：5xx 会为该任务打开异常，之后同一目标返回 2xx 时关闭异常。系统只保存规范化 URI 的哈希，不保存额外 URL 或正文；这只能说明当次 HTTP 状态，不能代表网页内容或整个服务健康。普通完成、其他目标成功、委派结果和用户自由文本都不能关闭异常。同一批并行检查对同一目标同时得到 5xx 和 2xx 时，不更新该目标状态。

投影最多显示该任务一个未解决的结构化异常及其来源 `Seq`。若没有这种异常，则显示最近一次普通工具失败线索，但它不代表业务状态。撤回或删除证据后，系统会根据仍可见的证据重新计算；撤回解决证据可能让较早的异常再次出现。重新检查必须按照当前指令实际执行，旧线索不能代替本轮结果。

## 规则

| 类型 | 写法 | 说明 |
|---|---|---|
| `cron` | 五段 cron 表达式 | 使用本机时区 |
| `interval` | 分钟数，≥ 1 | 从创建时开始计算 |
| `once` | 一个时间点 | 必须晚于当前时间，执行后标记为已执行 |

限制条件：内容最多 2000 字，间隔范围为 1 分钟至 1 年，最多创建 100 个任务。

## 页面管理

侧边栏的 **定时** 页面提供以下操作：

- 新建：选择规则并填写内容。日期时间选择器提供“1 小时后 / 明天 9:00 / 下周一 9:00”等快捷选项，不能选择过去的时间。
- 暂停 / 恢复：恢复时会跳过暂停期间错过的时间点，不会补发；应用关闭期间错过的触发也同样跳过。
- 删除。

目前没有编辑功能。需要改规则或内容时，请删除后重新建立，这样旧的发放记录不会吞掉新的触发。

## 让助手创建任务

主 agent 始终拥有 `schedule_create`、`schedule_list` 和 `schedule_delete` 三个工具，子 agent 没有这些工具。

- 工具结果包含当前本地时间，因此一次性任务可以直接写成“几分钟后”。
- 审批遵循输入区档位：“危险指令审批”只会询问删除；“全部审批”会询问创建和删除；列出任务永远不询问。
- 这样设计是因为任务到点后会被当成你发出的消息，不能让助手读到的网页悄悄替你创建一条任务。

## 存储

任务与发放记录分别追加写入 `<workspace>/scheduler/tasks.jsonl` 和 `receipts.jsonl`。
