# 对外服务（Memory Service）

**简体中文** | [繁體中文](./services.zh-TW.md) | [English](./services.en.md)

返回 [文档目录](./README.md)。

“对外服务”用于把外部 agent 和插件接入 Partner：让属于你的 Partner 对接任何兼容大模型的平台，比如游戏 AI mod、编辑器/浏览器插件或其他 agent 框架。应用可托管多个服务，每个占用独立 `127.0.0.1` 端口，透传 OpenAI 或 Anthropic 模型。它会在请求中注入主记忆召回，可选前置自定义提示词，并定期将交互总结写回主记忆库。

## 应用场景

游戏 mod、插件等通常自行连接模型，无法感知你的身份或历史上下文。将它们的模型地址指向对外服务，即可接入 Partner 的记忆系统；其交互内容也会自动汇总至主记忆，方便你在对话中随时查询。

接入前提：
- 程序支持自定义 Base URL、API Key 和模型名（多数支持 OpenAI/Anthropic 接口的 mod 均可）。
- 与 Partner 运行于同一台机器（服务仅监听 `127.0.0.1`）。
- 协议匹配（上游 OpenAI 选 `openai`，Anthropic 选 `anthropic`）。

接入步骤：
1. 在“对外服务”页添加服务并复制令牌。
2. 在 mod/插件中设置：
   - **Base URL**：`http://127.0.0.1:<端口>/v1`
   - **API Key**：服务令牌
   - **模型名**：配置指定的模型名称

## 核心机制

- **反向代理**：认证替换、模型名映射，其余参数（Tools, Stream, Response Format 等）原样透传。
- **无状态**：服务不保存会话，客户端负责维护历史。
- **记忆增强**：每次请求自动检索主记忆，注入到 user 消息前；可选前置自定义提示词。
- **自动总结**：定期将窗口期交互总结为一句话，写入主记忆，标记来源 `service:<id>`。
- **安全隔离**：仅监听 `127.0.0.1`，拒绝未经配置的模型名请求。

召回针对最后一条带文本的 user 消息进行，不支持 cross-service 召回。服务总结任务在交互结束后异步写入。

## 界面管理

侧边栏“对外服务”页：
- 创建服务，记录明文令牌（仅展示一次）。
- 实时监控：运行状态、请求量、待总结轮次及最近写入记忆。
- 卡片操作：立即总结、轮换令牌、删除（可选同时清理该服务记录的记忆）。
- 配置热更新：修改端口或协议需重启服务。

## 关键参数

| 字段 | 说明 |
|---|---|
| 名称 | 来源标签，摘要中显示 |
| 协议 | 必须与上游协议严格一致，不处理协议转换 |
| 上下文长度 | 默认继承主模型 |
| 召回/总结 | 可按需开启或关闭，配置 token 预算与总结周期 |
| 上游设置 | 可自定义 baseUrl、模型名、API Key 等 |

## 总结与超时控制

- 请求在 headers 到达前有超时限制（继承主模型或自定义设置）；响应流传输不限时。流式长回复请开启 `stream: true`。
- 上游返回的限流及重试头（如 `retry-after`, `x-ratelimit-*`）会原样透传给 SDK，方便客户端重试。

## 记忆删除与安全

> **服务记忆会写入主库，删除对话不会级联删除。**

在“服务”页删除服务时勾选“同时删除它写入的记忆”即可彻底清除。
*安全建议*：因外部内容会被总结写进主记忆，存在间接提示注入风险，仅允许受信任的客户端访问服务端口，并定期审查摘要。关闭“总结”开关可停止写入，已存记忆需手动删除。
