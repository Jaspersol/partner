# 語音功能

[简体中文](./voice.md) | **繁體中文** | [English](./voice.en.md)

返回 [文件目錄](./README.zh-TW.md)。

說一句話，它排入佇列、跑一個回合、把回覆念出來。語音和打字走同一條佇列，依到達順序執行。

## 鏈路

```
麥克風 → 停頓斷句 → ASR → 佇列 → 回合 → 工作階段
                                           ↓
喇叭 ← 依序播放 ← TTS ← 切句 ← 新的助手回覆
```

- 輸入和輸出各自啟動、各自回報錯誤。麥克風打不開，不影響朗讀。
- 只朗讀啟動後新出現的回覆，不會一開機就念歷史。
- 「朗讀時不聽麥克風」建議開啟，避免把助手自己的聲音當成你在說話。
- 「說話時打斷助手」：助手在說話時你開口約半秒就讓它停下。沒有回音消除，建議只在戴耳機時開啟。

## 兩種接法

| 接法 | 適合 | 設定位置 |
|---|---|---|
| 本機引擎 | 不想自己部署服務 | 設定 → 本機引擎，點「下載」 |
| 外部服務 | 已有 ASR/TTS 服務 | 設定 → 語音輸入 / 語音輸出，填服務位址 |

## 本機引擎：分開下載

安裝包只帶兩個小服務腳本。執行環境和模型不打包，依引擎單獨下載：

| 引擎 | 用途 | 佔用 | 大小 | 預設連接埠 |
|---|---|---|---|---|
| TTS（Qwen3-TTS 1.7B GGUF） | 朗讀 | 顯示記憶體約 1.9 GB | 約 3.0 GB | 45102 |
| KWS + ASR（sherpa-onnx + SenseVoice） | 喚醒 + 辨識 | 記憶體，純 CPU | 約 380 MB | 45103 |

- 只要辨識，就只下載 KWS + ASR，不需要顯示卡。
- 下載可續傳；有 SHA-256 就校驗；伺服器給了長度就核對，截斷不算成功。
- 連線中途斷掉會自動重試三次（從已下載的部分繼續）；60 秒收不到資料也當作斷線，不用重新按下載。
- 設定頁「偵測」依磁碟上的檔案判斷是否就緒，並列出缺了什麼。也可以手動指定已有的引擎目錄。
- 預設路徑存成相對於應用程式目錄，應用程式搬家或重裝不用改設定。
- 關掉開關 = 結束引擎行程（整棵行程樹），顯示記憶體與系統記憶體全部歸還。

下載位址可用環境變數覆寫：`PARTNER_ENGINE_TTS_URL`、`PARTNER_ENGINE_KWS_URL`（以及對應的 `_SHA256`）。
一個引擎可以由多個壓縮包組成（GitHub 單一 release 資產上限 2 GiB，TTS 裝不進一個），應用程式依序下載、逐個解壓到同一目錄。
發佈包用 `scripts/pack-engines.ps1` 從本機 `engines/` 產生：模型不進 git，腳本負責重打包可搬移的執行環境、切包、算 SHA-256，並印出要填進 `EnginePackage.cs` 的位址表。引擎 tag 是唯讀的：腳本發現同一 tag 上已有同名資產就直接失敗，換引擎就開新 tag（`engines-v2`），否則已發佈安裝包 pin 的 SHA-256 會全部失效。
每個包裡都有 `NOTICE/`：上游來源、變更說明、完整授權條文；這些授權與 MIT 無關，見 [THIRD-PARTY-NOTICES.md](../THIRD-PARTY-NOTICES.md)。

開發機可以用腳本裝進儲存庫的 `engines/`，設定頁能直接偵測到：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/install-engines.ps1              # 兩個都裝
powershell -ExecutionPolicy Bypass -File scripts/install-engines.ps1 -Engine kws  # 只裝辨識
powershell -ExecutionPolicy Bypass -File scripts/install-engines.ps1 -Engine tts  # 只裝朗讀
```

TTS 從 wav/mp3 複製音色時需要 `ffmpeg` 在 PATH 上；用內建的音色錨點則不需要。

## 喚醒

開啟 KWS 引擎後，語音輸入進入喚醒模式：麥克風一直在收音，但聽到喚醒詞之前不做辨識。

- 喚醒詞在「設定 → 語音輸入 → 喚醒」裡填，多個用逗號分隔；留空則沿用引擎裡現有的詞。
- 「喚醒後等你開口」預設 5000 ms，留給你想要說什麼；一開口就改依「停頓多久算說完」斷句。
- 可開「喚醒時叮一聲」，需要同時開啟語音輸出。
- 喚醒詞後緊接的話不會被截掉。

## 改設定的影響

改輸入、輸出、ASR、TTS 任一項會重新啟動語音宿主（重新開啟裝置）。只改模型不會，避免打斷正在進行的辨識。

## 已知邊界

- 完整迴路的自動化測試用的是合成音源，沒有在真麥克風上跑完整句。
- KWS 官方套件只有 chunk-16，喚醒延遲約 320 ms。
